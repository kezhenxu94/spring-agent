用这个工具为当前这一轮编码工作建立并维护一份结构化的任务清单。它帮你追踪进度、拆解复杂任务，也让
用户看得见你做得有多周全。它同时也让用户了解单项任务的进展和整个请求的整体进展。

## 什么时候该用这个工具
在以下这些情形下，主动使用它：

1. 多步的复杂任务 —— 当一件事需要 3 个或更多不同的步骤或动作时
2. 不轻松、有难度的任务 —— 需要仔细规划、或者要做好几步操作的任务
3. 用户明确要求用清单 —— 当用户直接要你使用任务清单时
4. 用户一次给了多件事 —— 当用户给出一串要做的事情时（编了号的，或用逗号隔开的）
5. 收到新指示之后 —— 立刻把用户的要求记成待办
6. 当你开始做某件事时 —— 在动手**之前**把它标记为 in_progress。理想情况下，同一时刻只应该有一个
   待办处于 in_progress
7. 做完一件事之后 —— 把它标记为 completed，并把实现过程中新发现的后续事项添加进来

## 什么时候不该用这个工具

在以下情形下就不要用它：
1. 只有一件事，而且很直接
2. 这件事很琐碎，把它记下来在组织上没有任何好处
3. 这件事用不到 3 个琐碎步骤就能做完
4. 这件事纯粹是聊天或者答疑

请注意，如果只有一件琐碎的事情要做，就不要用这个工具。这种情况下，直接把事情做掉更好。

## 校验规则

这个工具会校验以下几点：
- 同一时刻只能有**一个**任务处于 in_progress
- 任务的 content 和 activeForm 都不能为空或只有空白
- 所有任务的 status 都必须是合法值（pending、in_progress、completed）

## 任务状态与管理

1. **任务状态**：用这几个状态来跟踪进度：
- pending：任务还没开始
- in_progress：正在做（同一时刻限定**一个**任务）
- completed：任务已顺利完成

**重要**：任务的描述必须有两种形式：
- content：说明要做什么的祈使形式（例如"跑测试"、"构建项目"）
- activeForm：执行期间展示的进行形式（例如"正在跑测试"、"正在构建项目"）

2. **任务管理**：
- 边做边实时更新任务状态
- 做完就**立刻**把任务标记为完成（不要攒着一起标）
- 任何时刻都必须恰好有**一个**任务处于 in_progress（不能少，也不能多）
- 先把当前的任务做完，再开始新的
- 已经不再相关的任务，就整条从清单里删掉

3. **任务完成的要求**：
- 只有在你**完全**做成了的时候，才把任务标记为 completed
- 如果遇到错误、被卡住，或者做不完，就让这个任务保持 in_progress
- 被卡住时，新建一个任务来描述需要先解决什么
- 以下情况下绝不要把任务标记为 completed：
	- 测试还在失败
	- 实现只做了一部分
	- 你遇到了尚未解决的错误
	- 你找不到必需的文件或依赖

4. **任务拆解**：
- 建立具体的、可执行的条目
- 把复杂任务拆成更小、可管理的步骤
- 用清楚、有描述性的任务名
- 两种形式都要给出：
	- content："修掉认证的 bug"
	- activeForm："正在修认证的 bug"

拿不准的时候，就用这个工具。在任务管理上主动一些，既体现了你的用心，也能确保你把所有要求都做到。
