把一份文档存入知识库，或者更新已经存在的那一份，以便在以后的对话里被回想起来。

用法：
- scope 选择存进哪个知识库："own"（默认，只有这个用户可见）、"group"（与当前群聊里的所有人共享）
  或 "tenant"（与整个公司共享）。
- title 是这份文档在列表里显示的名字；写得足够具体，以后能一眼认出来。
- source 是这份文档的来源，之后会展示给读者，让他们能去读原文。它要么是用户、群或公司工作区内某个
  文件的绝对路径，要么是一个网址——一个 wiki 页面、一张工单、一个 pull request。
- text 是内容本身。不填它，就把 source 当作文件去读；填了它，source 就只用来说明内容出自哪里——
  当你抓取了一个页面并要把它的正文存下来时，这正是你想要的。
- 有来源就一定要填 source。文字本身不带来源，缺了它，存下来的文档就再也追溯不回它出自的那个页面，
  读者只会看到一个标题、点不开任何东西。只有当内容纯粹是用户口头告诉你的，才可以不填，这时会把你
  正在回答的那条消息记为来源。
- docId 是必填的，它就是“这份文档是什么”的标识。用同一个 id 再存一次，是替换；换一个 id，就是又存
  了一份，它会和第一份一起被搜到，并且与之矛盾。所以要用你手上的信息做出最好的 id——取这份内容里
  下次再遇到时仍然相同的那个东西：
  - 飞书文档、wiki 页面、表格或多维表格：取它链接里的 token，也就是 /docx/、/wiki/、/sheets/ 或
    /base/ 之后的那一段。就按链接原样取；一个 wiki 链接和它背后的文档是两个链接，算作两份文档。
  - 从网上抓取的页面、工单或 pull request：它的 URL。
  - 工作区里的文件：它的绝对路径。
  - 用户在这次对话里告诉你的事：他们说这话的那条消息的 id。
  - 你此前存过、现在要修订的文档：它在 ListKnowledgeBase 里的 id。
- 如果以上都不适用——内容没有你能指明的来源，或者两样东西你分辨不出——那就用 AskUserQuestionTool
  问用户该归档到哪个 id 下，不要自己编。编出来的 id 看着像成功了，等下次再谈到这个主题时就会多出
  一份副本，而在两份副本于某个回答里自相矛盾之前，没人会发现。
